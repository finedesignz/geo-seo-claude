### 2. Worker failure routing (D-13 + D-15)
- All `ScoringError`s carry `retryable: true` and one of `SCORING_TIMEOUT | SCORING_RATE_LIMITED | SCORING_API_ERROR | SCORING_MALFORMED_OUTPUT`. (Malformed is retryable — ROADMAP success criterion #4. MAX_ATTEMPTS bounds it.)
- In `runAudit`: catch `ScoringError` → if `job.attempts < MAX_ATTEMPTS` call `dal.requeueJob({id, leaseToken, errorCode})` else `dal.failJob({id, leaseToken, errorCode})`. Deterministic fetch error (`FetchErrorCode`, incl. core sub-fetch) → `dal.failJob` directly (not retryable). `completeJob` ONLY on the success path.
- **acceptance_criteria (worker.test.ts / pipeline.test.ts):** assert `completeJob` call-count == 0 on every failure path; assert a retryable scoring failure with attempts<MAX calls `requeueJob` (not failJob); assert attempts>=MAX calls `failJob`; assert a core sub-fetch error short-circuits to failJob with no `messages.create` call.

### 3. Lease-fenced boolean + no unhandled rejection (D-16)
- Treat `false` from `completeJob`/`failJob`/`requeueJob`/`renewLease` as lease-loss: log it, do NOT re-write, end the audit (another worker owns the job).
- Track in-flight audits in a `Set<Promise<void>>`; each entry is `runAudit(...).catch(logAndMarkFailed).finally(() => inflight.delete(p))`. The loop never `await`s a bare fire-and-forget without `.catch`.
- Check `signal.aborted` immediately before the scoring call and before each DAL write; if aborted, stop without writing.
- **acceptance_criteria:** a test forces `completeJob`→false and asserts no throw + lease-loss logged; a test makes `runAudit` reject and asserts the process does not emit an unhandledRejection and the slot is freed.

### 4. WorkerOptions completeness + signal-handler cleanup (D-16)
- Extend `WorkerOptions` in `packages/worker/src/types.ts` to carry everything `runWorker`/`runAudit` need: `dal`, `scorer`, `makeFetcher` (or `fetcher` factory), `concurrency`, `leaseTtlSeconds`, `reclaimIntervalMs`, `pollIntervalMs`, `maxAttempts`, and an injectable `clock`/`sleep` + `setInterval`/`clearInterval` seam for deterministic fake-timer tests.
- Register SIGTERM/SIGINT in `runWorker` and REMOVE them in the shutdown `finally` so repeated test invocations don't accumulate listeners.
- **acceptance_criteria:** `tsc` clean with `runWorker(opts: WorkerOptions)` consuming all fields; a fake-timer test drives reclaim + heartbeat via the injected seam; a test asserts SIGTERM listener count returns to baseline after shutdown.
